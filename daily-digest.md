## iOS Tips (Swift / SwiftUI)

### 1. The `#if compiler(>=6.2)` + `#available` Double-Guard Pattern

You're already using this in `GlassEffectModifier.swift` and `GlassEffectContainerView.swift`. It's worth internalizing *why* both guards are needed: `#available` is a runtime check, but new APIs may not even *compile* against older SDKs. The `#if compiler(>=6.2)` guard tells the compiler to skip the block entirely when building with Xcode < 26, avoiding "unknown type" errors at compile time. Always pair them when adopting iOS 26 / Xcode 26 APIs.

```swift
if #available(iOS 26.0, *) {
#if compiler(>=6.2)
    content.glassEffect(.regular, in: Capsule())
#else
    content
#endif
} else {
    content
}
```

### 2. Measure View Size via `GeometryReader` in `background`, Not in the Layout

`BottomSheetView.swift` uses a `ReadSizeModifier` that injects a `GeometryReader` via `.background(sizeView)`. This is the correct approach — putting `GeometryReader` directly in a layout position causes it to expand greedily to fill available space. Placing it in `.background` or `.overlay` gives it the same frame as the content without affecting layout.

### 3. `contentTransition` for Animating Number and Text Changes

`ContentTransitionModifier.swift` exposes `.numericText(countsDown:)` — a lesser-known modifier that animates digit changes with a rolling effect. Great for counters, timers, or scores. Pair it with `withAnimation` on the binding that drives the value; SwiftUI handles the rest.

```swift
Text("\(score)")
    .contentTransition(.numericText())
    .animation(.default, value: score)
```

[Docs](https://developer.apple.com/documentation/swiftui/contenttransition/numerictext(countsddown:))

### 4. `glassEffectID` Requires a `Namespace` — Guard Against Missing Ones

`GlassEffectIdModifier` correctly checks that `NamespaceRegistry` has a namespace before calling `.glassEffectID(_:in:)`. This is important: passing an invalid or stale namespace causes a runtime crash on iOS 26. Keep the registry as the single source of truth and always nil-check before applying the modifier.

## Android Tips (Kotlin / Jetpack Compose)

### 1. `@file:OptIn` vs Per-Site `@OptIn` — Know the Blast Radius

`BottomSheetView.kt` uses `@file:OptIn(ExperimentalMaterial3Api::class)` and `PullToRefreshBoxView.kt` uses `@file:OptIn(ExperimentalMaterial3ExpressiveApi::class)`. A file-level opt-in silences warnings for *every* call site in the file. Prefer per-function `@OptIn` when only one composable in the file uses the experimental API — it limits the blast radius if the API changes and makes review diffs clearer.

```kotlin
// Prefer this when only one function needs it:
@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun MySheet() { ... }
```

### 2. `rememberCarouselState` Takes an `itemCount` Lambda, Not a Value

In `CarouselView.kt`, `rememberCarouselState(0) { view.size }` passes `itemCount` as a trailing lambda. This is intentional — Compose reads it on each recomposition, so it's always in sync with the data list. If you pass a captured `Int` instead, the state won't update when the list grows. Always use the lambda form.

```kotlin
val state = rememberCarouselState(initialItem = 0) { items.size }
```

[Docs](https://developer.android.com/reference/kotlin/androidx/compose/material3/carousel/package-summary#rememberCarouselState)

### 3. Combine `AnimatedVisibility` Transitions with `+`

`AnimatedVisibilityView.kt` reduces a `List<EnterTransitionRecord>` using `acc + transition`. In Compose, `EnterTransition` and `ExitTransition` are composable via `+` — the result runs both animations simultaneously. This means you can build `fadeIn() + expandVertically()` from a JS-driven config array without any custom animation logic on the native side.

### 4. `FloatingToolbarScrollBehavior` via `nestedScrollConnection`

`HorizontalFloatingToolbarView.kt` casts `composableScope.nestedScrollConnection` to `FloatingToolbarScrollBehavior` to get scroll-aware FAB hiding. If the scroll container is a `LazyColumn` or `ScrollView` hosted outside this composable, the `nestedScrollConnection` must be wired up at the *parent* level — otherwise the toolbar never receives scroll deltas and stays permanently expanded.

[Docs](https://developer.android.com/reference/kotlin/androidx/compose/material3/FloatingToolbarScrollBehavior)
